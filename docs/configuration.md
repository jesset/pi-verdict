# Configuration Reference

Everything the gate reads from disk lives in `<agentDir>/config/pi-verdict.json` (first run generates a template there; `PI_CODING_AGENT_DIR` overrides the location). This page is the full reference; the README keeps a quick-start subset.

## User rules

```json
{
  "allow": ["^ls\\b", "^git (status|log|diff)\\b"],
  "deny":  ["rm ", "docker ", "^/etc/"],
  "denyPaths": [
    "~/.ssh/",
    "~/.profile",
    "~/.gnupg",
    "~/.mc",
    "~/.zshrc",
    "~/.bashrc"
  ],
  "builtinDenyFloor": true,
  "classifierModel": null,
  "toggleShortcut": "ctrl+shift+a"
}
```

- `allow`/`deny` are JS regex arrays; **`deny` wins over `allow`**, both beat the classifier. Match targets: bash/powershell = the full command string; file tools = the resolved absolute path (`grep`/`find`/`ls` with an omitted `path` resolve to the cwd — pi's documented default); other tools (e.g. MCP) are not covered by rules and land in the gray zone.
- `denyPaths` are plain paths (not regexes) you declare **protected**: any tool call touching them — file tools via their path (scope tools via their whole search scope: omitted path/cwd, or a parent directory of a declaration), bash via path tokens extracted from the command string — triggers a **terminal ask** you adjudicate (non-interactive sessions degrade to deny). Not affected by `builtinDenyFloor: false`. The first-run template pre-fills a starter list (`~/.ssh/`, `~/.gnupg`, `~/.mc`, shell rc/profile files), active from the first session after the initial run — a pre-filled user declaration you can edit or empty; existing configs are never rewritten.
  The classifier only ever learns that protected paths *exist*; the paths themselves never leave your machine, and a matched path shows **only** in the local confirm dialog.
- `builtinDenyFloor: false` turns the built-in danger/path floor off entirely (risk accepted by you; the classifier and your rules remain — the self-protection layer always stays on).
- `classifierModel: "provider/model-id"` sets the classifier model (e.g. a fast flash-class model); precedence is flag > env > config > session model (self-reflection); an invalid value falls back to the session model with a one-time warning.
- The spec accepts pi's native `--model` thinking suffix: `"zai/glm-5.3-flash:low"` sets classifier thinking to effort low (default without suffix: thinking explicitly off).
- `classifierModel: "typesafe/jev-latest"` opts into the bundled **jev decisions adapter** (`extensions/jev-adapter.ts`, loaded with the package; disable it individually with `pi config`). Gray-zone verdicts become one `choice` question against TypeSafe's jev decisions API; the typed answer is synthesized into the usual `<verdict>` text with probabilities and confidence, so timeouts and fail-closed semantics are unchanged. Two transports (`PI_VERDICT_JEV_TRANSPORT`, default `openrouter`): **OpenRouter** sends to `POST /api/alpha/decisions` (an alpha API) and reuses pi's OpenRouter login (`/login openrouter`) with `OPENROUTER_API_KEY` as fallback — no separate typesafe account; **typesafe** sends to TypeSafe's official `POST api.typesafe.ai/v1/systemone` with `TYPESAFE_API_KEY` (self-service at console.typesafe.ai — pi has no typesafe login, so this is that transport's only credential source). The two wire contracts are isomorphic except for the model slug; the TypeSafe API does not report per-call cost (it shows as $0). `PI_VERDICT_JEV_URL` overrides whichever transport is active. Thinking suffixes are meaningless for jev and are ignored. Caveats ([ADR-0003](adr/0003-jev-decisions-adapter.md)): the denyPaths existence hint does not reach jev (denyPaths themselves stay rule-enforced before the classifier); jev treats the transcript as data and "does not treat it as hostile by default" (TypeSafe docs), so adversarial transcript content can move its judgment; omp hosts cannot load the adapter and the setting falls back there.
- `toggleShortcut` rebinds the master-switch toggle key (`null` or empty disables it, not persisted).
- `audit: true` turns on the **verdict audit log** (#54): every gray-zone adjudication appends one self-contained JSONL record to `<agentDir>/verdicts/<sessionId>.jsonl` — timestamp, session id, cwd, model id, tool name + input, action line, thinking level, the full transcript sent, the raw response text, the parsed verdict + reason, source (`model`/`fail-closed`/`protected-path`), shadow-cache probe result, and the degraded flag. Rule-layer allow/deny decisions are never recorded; **protected-path asks are recorded** (#62) — their confirms are user adjudications that grade the denyPaths rules (the record carries the matched path in `detail`). Interactive asks (classifier and protected-path alike) record **ground truth** (#62): the record is written after the confirm resolves, carrying `userAnswer` (`allowed`/`declined`) and `answeredAt` (`ts` stays adjudication time); a non-interactive degraded ask records immediately as its effective deny, without the answer fields. Accepted trade-off of the deferred write: closing pi while a confirm dialog is open loses that ask record (one record per verdict, append-only — no pre-write/rewrite). Records of triggered calls carry an optional `fallback` sub-object when the second layer is configured (#63 — see above for its reading discipline). Retention keeps the 20 most recent session files (pruned at session start). Full fidelity by design: records may contain protected-path plaintext — that stays inside your machine ([ADR-0002](adr/0002-deny-paths-deterministic-ask.md) boundary note), and the directory is denied to agent reads *and* writes (records contain untrusted raw model output, including fail-closed failures). The sink is fail-soft: a write failure never affects or delays a verdict — one warning, then silent for the rest of the session. Never an adjudication input: append-only, never read back into gate decisions (shadow-cache discipline). `/automode` shows `audit: on → <path>` while active. Off by default; no `verdicts/` directory is created unless a recordable adjudication happens with audit on.
- `notifyAllows: true` surfaces every **classifier allow** as an info notification (verdict reason + action line) — the gate's judgment calls become visible, e.g. jev's probability breakdown (`jev: allow 66% (confidence 49%; ask 33%, deny 1%)`). Default `false`: notifications stay limited to what needs your attention (deny/ask/warnings) and passes stay silent. Mechanical passes never notify under this option — allow-rule hits are echoes of your own declarations, and a protected-path confirm's visibility is the dialog itself; complete records live in the verdict audit log instead. Orthogonal to the debug switch: shadow-cache annotations stay debug-only, and with both on the classifier-allow notification appears exactly once (with the shadow suffix). Config-only, new-session semantics.
- `classifierFallbackModel: "provider/model-id"` adds an opt-in **second-layer classifier** consulted only when the first layer is uncertain ([ADR-0004](adr/0004-classifier-fallback-cascade.md)): trigger precedence is first-layer **fail-closed → `ask` → jev confidence strictly below `classifierFallbackConfidence`** (number 0–100, default 50; invalid values skip into the one-shot warning channel and default; the rendered confidence floors, never rounds, so a true 49.6% cannot slip past a 50 gate). Unset (the default) = the cascade is entirely off — zero extra model calls, behavior identical to today. LLM first layers carry no numeric confidence, so their gate is ask/fail-closed only; jev's confidence is hard-required by the adapter (contract drift fails closed). The second-layer call gets its own 15s-per-attempt budget (the two-tier retry can double it, mirroring the first layer's per-attempt 25s) and, unlike jev, receives the denyPaths existence hint. Resolution is config-only and never falls back to the session model; an unresolvable model warns once per session.
- `classifierFallbackMode: "shadow"` (default) — the fallback runs on triggered calls, its outcome lands in the audit record's `fallback` sub-object and in `/automode` session counters (`triggered · agreed · would-escalate · errored`), and **the effective verdict never changes**. `"enforce"` applies a **safety ratchet**: the effective verdict is the stricter of the two (allow < ask < deny — the fallback may only escalate, never relax; escalations annotate the reason with `second-opinion classifier escalated X to Y`). In enforce a **failed fallback call or unresolvable model denies the triggered call** (a configured second layer must not silently degrade to single-layer); untriggered calls stay single-layer. In any mode, audit records keep **first-layer semantics at the top level** — the enforced outcome lives in `fallback.effective` (enforce rows only, including failure rows, where it is `"deny"`), so read enforce rows through the sub-object; on non-interactive records an `effective` of `ask` was applied as its deny degradation (the usual ask-degradation rule). Shadow→enforce flip is a human decision after shadow data ([criteria](adr/0004-classifier-fallback-cascade.md)); config-only, new-session semantics.

## Why no built-in allowlist?

Bypass testing of the rule layer ([writeup](../research/rule-layer-security-audit.md)) showed that allowlist robustness is very limited. The built-in layer only makes **deny** claims (the sound direction); allow claims are yours.

## Host notes (pi and oh-my-pi)

pi-verdict runs on both [pi](https://github.com/badlogic/pi-mono) and [oh-my-pi](https://github.com/can1357/oh-my-pi) (omp); the extension self-anchors to whichever agent tree it is installed in. On a dual-install machine the gate follows the extension copy's own location — the mere presence of `~/.omp` never redirects a pi run (and vice versa).

Implementation details worth knowing if you hack on the extension:

- omp 18's `ModelRegistry` has no `complete` method, so the classifier resolves completion through the pi-ai compat module at first gray-zone verdict (`@earendil-works/pi-ai/compat`, which omp's legacy compat layer rewrites to its bundled pi-ai). Resolution or call failures follow the usual fail-closed deny.
- Thinking control is sent in both hosts' native dialects (`thinkingEnabled`/`effort` for pi, `reasoning`/`disableReasoning` for omp); each host reads its own fields and ignores the other's.
- omp installs npm plugins under `plugins/node_modules/<pkg>/` in its config root — under `<agentDir>/` up to omp 18.0, a sibling of `agent/` since omp 18.1; both layouts get the same whole-package-dir self-protection as the pi forms (ADR-0001). The user-rules config always lives under `<agentDir>/config/` on both layouts.
